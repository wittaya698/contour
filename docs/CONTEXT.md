# Contour — domain context

Shared vocabulary for this repo. When a word here appears in a spec, a commit
message, or a conversation, it means what this file says it means.

## Vocabulary

| Term | Means |
|---|---|
| **model space** | One model's own directory and its own git repository, found by walking up from the working directory for `.contour/project`. Never pushed (ADR 0011, ADR 0015). Spaces coexist; a variation of a model is a new space. One module answers where a space is, what it contains, and where spaces are found — `lib/space.py` — asked about a space rather than about the process asking, so the launcher, the console and the Blender side read one table instead of three. |
| **variant** | The old word for a model space, from when each model lived on a long-lived branch of this repo (ADR 0003, retired by ADR 0015). It survives in older ADRs and in some code identifiers. |
| **spec** | `spec.yaml` at the root of a model space. The user's intent, expressed in numbers. Agent-read-only. The definition of correct. |
| **reference** | An image the user supplies, stored in `refs/` at original fidelity: their intent in pictures, in the spec's trust class (ADR 0012). Say *reference*, not "model picture" — and never *sheet*, which is Contour's own render. |
| **anchor** | The one real-world dimension the user states for a set of references, in millimetres. Every other size read off those images is a pixel ratio against it. Pictures carry proportion, never scale, so without an anchor the agent does not draft `dimensions` — it asks. |
| **mark** | A located comment: a position, one line of text, an author, and a status. The unit both sides use to point at a thing on the picture (ADR 0018). A **sheet mark** says *the build is wrong*; a **ref mark** says *here is what I meant*. One module owns both the file and the record — `lib/marks.py` — with a named birth for each of the three ways a mark comes into being and a named transition for each state change below, so the lifecycle is enforced in one place rather than as comments in whichever module performs it. |
| **pin** | Where a sheet mark actually is, once a ray has resolved it: a point in the hit part's own coordinates. Pixels lie the moment geometry moves; a pin moves with its part, and is *orphaned* — said so, in the file — if that part is deleted. A part's *name* is not a position, so the two stopped sharing a key: the part is named at the top level of the record and the anchor holds the pin alone. A space marked on before that keeps the old spelling until someone runs `contour migrate-marks`, which `contour doctor` counts and nothing does on load — `marks.json` is tracked, and a rewrite of the user's own findings is a state they choose and see. |
| **badge** | A pin drawn on the sheet: the mark's id, painted over background pixels only and leashed to its pin, so the model is never covered by a remark about it. |
| **anchored** | Of a mark: resolved from a pixel to a pin (ADR 0018). The rays are cast at the last moment before geometry can change, because a ray has to hit the build the sheet was drawn from: under a **console** that is the instant a build's **gate** is approved, and under `contour canvas` it is still the moment the user says Done, since that host owns no build and cannot know of one coming (ADR 0019). Unrelated to **anchor** above, which is a millimetre figure about references. The sheet is anchored in parts, the references are anchored in millimetres, and nothing is both. |
| **span** | A ref mark with two ends instead of one: *this distance, right here*. It is what aims `contour measure` at a separation, which a scanline can only guess at because it finds runs and cannot know which two the question was about. The answer comes back as an agent mark pinned between the two pins, in millimetres against the space's stated height, and states its own error bar (ADR 0018). |
| **addressed** | What the agent may attach to a mark: *I believe this build deals with it*, stamped with that build's id. It dims the badge and is **not** a close — only the user closes a finding, because a finding is not disposed of by the party it is aimed at (ADR 0018). |
| **console** | The browser surface above the launcher, from which a run is driven and gated (ADR 0019). Its own executable, `contour-console`, beside `contour`: two names so the install boundary is legible where somebody meets it, since the console is the one part of Contour that is not stdlib-only. It serves the **canvas**'s page and the canvas's server rather than copies of either, and reads state by importing `lib/`'s Blender-free half while acting by spawning `./contour` — it spawns Blender and must never contain it. Long-lived, and still ends when the page says done: the page beats, and a page that stops beating is a tab that closed. An idle timeout ends the tab left open on Friday, and a pending gate suppresses it, because silence is not a verdict. |
| **capability** | Something a host of the **canvas**'s page can do, which the page asks about rather than assumes (ADR 0019). One page, two hosts: served by the launcher it can `marks` and nothing else, served by the **console** it can also `drive`. An affordance declares the capability it needs, or the one it stands in for, and a single rule removes whatever the host did not grant — so marking survives in a clone with no environment, and a name the page has never heard of is ignored rather than shown. A second page for the second host was rejected as a bundler with a delay. |
| **run** | One agent session the console drives, from the first prompt to the agent stopping. Not a **build**, which is one execution of `build.py`; a run contains many. |
| **transcript** | The run as it happens, on the page: the prompt, what the agent said, the calls it made, each **gate** and the verdict given (ADR 0019). A cursor over a list rather than a stream, so a reloaded tab gets the whole run back and not whatever happened after it reconnected. It is where a decision becomes visible, which is what makes the console a control surface rather than a progress bar — and a **veto** is the part of it that outlives the session. A limit the harness reports appears here and ends nothing: a limit the user did not choose must not interrupt work they were watching. |
| **gate** | A point where a tool call stops and waits for the user (ADR 0019). Not a **checkpoint**: a checkpoint is the agent saying *I think I am done*, and a gate is the console saying *not until you say so*. One is the agent's judgement, the other is the user's authority. A build's gate is also where marks are **anchored**: it is the instant before geometry changes, so putting the build on the ask-list means the only thing that can invalidate a mark is a call the user approved — and there is no second concurrency story to own (ADR 0019). |
| **ask** | The third verdict beside allow and deny. What `tools/guards/spec.py` could not say, and the reason ADR 0016 traded prevention for detection *knowingly*. With it, a spec write pauses instead of being refused or merely noticed afterwards. |
| **ask-list** | The policy naming which **categories** of call run unwatched. An allow-list with no presets — a category it does not mention is gated, so one the toolkit gains later arrives as a gate that is noticed and then decided. Two levels, a global list and a per-space one, and the space's replaces the global whole: merging two permission lists can silently shadow a rule in either file. A space the list never names lets nothing through. Lives in `~/.contour/ask-list.yaml`, never in a space, and never written by the agent — which may propose a wider one and nothing more. An ask-list is a check, so rule 2 covers it. `contour asks` prints the resolved one (ADR 0019). |
| **category** | What a call *means*, in Contour's vocabulary: a spec write, a ref write, a build, a commit, a push. The unit an **ask-list** is written in, and what the launcher answers when the console asks about a call rather than pattern-matching its text — one intent has several spellings, and a permission list needing one rule per spelling will still have a hole (ADR 0019). `contour intents` prints the set, because a list that cannot be printed cannot be audited. |
| **veto** | A denied call and the reason for it, authored by the user at a gate and tracked in the space (ADR 0019). Not a **mark**, which has a position and is *the build is wrong* or *here is what I meant*; a veto is *not this* — authority exercised against one call at one moment. Only the user can veto, as only the user closes, and a call refused because the **run** was ended is not one: nobody considered it. It carries the call, the reason, the author and the **build** it happened against, in its own tracked file beside `marks.json` and never inside it — a veto is never resolved, so the rule that prunes closed marks would delete the only record that something was prevented. It reaches git with the change it prevented, never in a records-only commit, and the console's whole contribution to that is a number on the page: *n vetoes uncommitted*. `contour check` says nothing about one, because a veto is never open and a status line that never goes away is furniture. A veto about a part may be **promoted** to a sheet mark, which is what gives it a position — the part is named by the user, and the mark it becomes is badged from the identity mask like any mark that names a part and no point on it. |
| **seed** | The open marks a run was started from, which the console composes into that run's prompt: a mark is the one place the user's intent is already located, authored and tracked, so *these two* is a complete request and prose is optional beside it (ADR 0019). A seed the store cannot honour — closed, pruned, never there — is dropped and the drop is named in the prompt, because a scope silently one shorter is the dropped finding this exists to prevent. Seeding is what makes **addressed** checkable: the console knows what was in scope, so at the end of the run it says, of each seeded mark, `addressed in build N`, `unaddressed`, or `orphaned` when the build deleted the part it pointed at — a part that is gone does not answer the question asked about it, so orphaned is said over any claim. It is a report and nothing else: seeding closes no mark and writes nothing to the store, because only the user closes a finding. *Addressed* means addressed by **this** run, so the stamp a mark carried when it was seeded is remembered and compared — a claim from two builds ago is not this run's work. |
| **spend** | What a run costs, per turn, recorded where the accounting can read it (ADR 0019). The SDK reports usage per turn with cache reads broken out — strictly better than anything a Claude Code transcript could be parsed for — so the console appends one line per turn in its space's own `.contour/`, and `tools/tokens.py` reads it beside the transcripts it already reads: one run is one **iteration**, weighed by one set of multipliers held in one place, so a console run and a terminal iteration are comparable rather than merely adjacent. Shown live on the page in those same units, because the display has a second job — a **gate** buys a turn of re-explanation every time, so each line records how many gates preceded it and the report says what the post-gate turns cost, which is what makes *tune the ask-list downward* an informed act rather than an irritated one. It is a measurement and never a governor: no budget, threshold or limit ends a run, on the idle timeout's symmetry — a threshold set before the user knew what the run involved is no more a verdict than silence is — and nothing is shown before a turn has actually been spent, because a pre-run estimate cannot be known and a wrong one is worse than none. |
| **build** | Running the space's `build.py` under headless Blender to produce `out/<name>.blend` from an empty scene. |
| **verify** | Running `verify.py` against a build, judged by its spec. Produces a pass/fail line per check. |
| **measurement** | What a **verify** check is judged over: summary numbers, one record per part — a face-degree histogram, counts of non-manifold edges and loose geometry, how many faces point the wrong way, and how close the closest two vertices came, the world box the part occupies, its scale and rotation, its UV layers and the materials in its slots. Beside the records it carries the name of every object in the scene, mesh or not, because one check is about the scene rather than about any part — a stray empty is a part list that does not match, and a measurement of meshes alone would not see it. No `bpy` object and no `bmesh` handle survives the gather, which is what lets a check be exercised from a record written by hand, with no Blender and no fixture (ADR 0020). `lib/measure.py` gathers it inside Blender; `lib/checks.py` judges it outside, and `verify.py` is what is left: gather, judge, print. The reading, never the instrument — a gather that hands back the instrument leaves every caller holding a lifetime and every check needing Blender to run, which is why there is no `release()` to forget. |
| **green** | A verify report in which every check passed — `PASS`, and `contour` exits 0. The word the code itself uses (ADR 0005 budgets ~50 tokens on green). |
| **red** | A report in which any check failed — `FAIL n/total`, one line per failure, exit 1. A build that dies before verify runs is red too. Rule 2: red is a finding, never something to be made to go away by changing what was asked. |
| **checkpoint** | A moment the agent believes it is done or is stuck, and says so. In a terminal it triggers a render sheet and a request for approval; under a **console** the **panel** is already current, so a checkpoint is the agent's judgement alone and no longer means *render now* (ADR 0019). Never the same as **green**: green is the spec satisfied, a checkpoint is the agent claiming to be finished — or admitting it is not getting there. |
| **panel** | The **sheet** on the page, beside the **transcript** in an equal split, labelled with the build it was drawn from (ADR 0019). Every build renders for it and only a checkpoint renders for the agent: the ~1400 tokens a sheet costs are a cost to the agent's context, not to the render, so a picture going to a page can be current. A build that never finished leaves the last good sheet, said to be not current — a partially built scene is never rendered, because that is a picture of a model that has never existed in the place where every other picture is real. No failing check is overlaid: a check knows a number, not a location, so some failures would draw and others would not, and absence would stop meaning anything. |
| **sheet** | The 4-view orthographic Workbench render (front / right / top / persp) at 1024², with a 1 m grid and scale bar. The agent's only eyes. |
| **round-trip** | Re-importing an exported file into a clean Blender and re-measuring it there. The only proof an export is correct. |
| **toolkit** | This repository: `lib/`, `verify.py`, `schema/`, `templates/`, `.claude/`, `fixtures/`, `tools/`. Shared and pushable, and builds no model of its own. Every space uses it through the `contour` launcher. |
| **fixture** | `fixtures/smoke/` — a trivial shape existing only to exercise the pipeline. Never a deliverable. |
| **generated file** | `out/<name>.blend` in a model space. Read-only output. Regenerated from zero on every build. |
| **working file** | `work/scene.blend`. Yours. Links the generated collection. Git-ignored. Never read by the pipeline. |

## Pipeline stages

```
spec ──┐
       ├──> build ──> out/<name>.blend ──> verify ──> report (~10 lines)
       │                    │
       │                    ├──> render ──> sheet.png          (every build; into
       │                    │                                    context only at a
       │                    │                                    checkpoint)
       │                    │
       └──────────────────> └──> export ──> exports/<name>.glb ──> round-trip ──> re-measure

                       every path is relative to the model space (ADR 0015)
```

Every stage is reachable through `contour` and nothing else. The wrapper
exists to keep Blender's stdout out of the conversation; the full log always
lands in `.contour/last-build.log` for when a stage fails.

## The three priorities, and what each one bought

Stated priorities, in order: **correctness**, **token usage**, **version control**.

- **Correctness** bought: the spec being agent-read-only (so the goalposts
  cannot move), `bmesh` over `bpy.ops` (so headless context cannot silently
  corrupt a build), orthographic multi-view renders with a scale reference (so
  misalignment and wrong scale are visible), and export round-tripping.
- **Token usage** bought: the `contour` wrapper's terse reports, a sheet
  entering the conversation only at a checkpoint — the render itself runs on
  every build, for the **panel**, which costs no context (ADR 0019), three-layer docs so `CLAUDE.md` stays ~40 lines,
  and `contour api` so the agent looks up signatures instead of guess-failing.
- **Version control** bought: deterministic rebuilds (a commit fully describes a
  model), source-plus-thumbnail tracking, a repository per model that is never
  pushed, and a human approval gate so every commit is a state you chose.

## Known constraints

- Blender is **5.2.1 LTS, built 2026-08-25** — after the assistant's knowledge
  cutoff. Recalled `bpy` API details are unreliable; `contour api` is
  authoritative.
- Blender is Z-up, right-handed, 1 unit = 1 m. Every engine target differs; the
  export step converts and the round-trip proves it.
- The `.blend` format is opaque to git. It is treated as a build artifact, not
  as source.
